# openp41ge-components — Shared Component Library with Storybook

## Goal

Create a `openp41ge-components` library package providing reusable UI components (`<openp41ge-icon>`, row components, layout primitives) styled with Tailwind CSS, scoped via Shadow DOM. Each package compiles and ships its own CSS alongside JS, with Storybook for visual development.

## Rationale

The git sidebar should match the explorer sidebar's visual style. Rather than duplicating inline styles across each sidebar view and having dozens of icon-export functions, extract shared primitives into a component library. Components use Shadow DOM + Tailwind for scoped, consistent styling.

## Approach

### Tailwind Architecture — Self-contained per-package builds

| Context                       | Pipeline                                                                             |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `openp41ge-components` build  | `tailwindcss CLI → dist/styles.css` + `inline-css script → generated/tailwind.ts` + `vite build` |
| `openp41ge-components` storybook | PostCSS plugin processes `src/styles.css` at dev time                               |
| Main app (`openp41ge`) build  | Imports `"openp41ge-components"` — JS has inlined CSS for Shadow DOM; or imports global CSS from `dist/` |

### Build Pipeline (per package)

```
Step 1: tailwindcss -i src/styles.css -o dist/styles.css
        → Compiles @tailwind utilities; into expanded CSS using the package's tailwind.config.js
        → Output: dist/styles.css (for consumers who want global stylesheet)

Step 2: node scripts/inline-css.mjs
        → Reads dist/styles.css, writes src/generated/tailwind.ts
        → Output: export const tailwindCSS = `.flex { ... } .text-sm { ... }`;

Step 3: vite build
        → Bundles JS. Components import from ../generated/tailwind and use
          the string in Lit's static styles via unsafeCSS()
        → Output: dist/index.js
```

### How components use the inlined CSS

```ts
// src/components/repo-row.ts
import { LitElement, html, unsafeCSS } from "lit";
import { tailwindCSS } from "../generated/tailwind";

export class RepoRow extends LitElement {
  createRenderRoot() {
    return this.attachShadow({ mode: "open" });
  }

  static styles = unsafeCSS(tailwindCSS);

  render() {
    return html`<div class="flex items-center p-2 cursor-pointer hover:bg-white/5">...</div>`;
  }
}
```

The shadow root contains the compiled Tailwind utilities, so all class names resolve correctly inside the component. No global CSS leakage, no conflicts between libraries.

### How the main app consumes it

**Option A: Import the JS (CSS is inlined for Shadow DOM)**

```ts
import "openp41ge-components";
import { RepoRow } from "openp41ge-components";
```

No extra CSS import needed — the compiled Tailwind is bundled inside the JS as a string that components use in `static styles`.

**Option B: Also import the global stylesheet** (for non-shadow-DOM contexts)

```ts
import "openp41ge-components/dist/styles.css";
```

### Shared design token preset

```
tailwind.preset.js (monorepo root)
    │
    ├── packages/openp41ge-components/tailwind.config.js
    │     └── presets: [require("../../tailwind.preset.js")]
    │
    └── (future) packages/openp41ge-X/tailwind.config.js
          └── presets: [require("../../tailwind.preset.js")]
```

The preset defines all design tokens (colours mapped to CSS custom properties, font sizes, spacing) so every library shares the same visual language.

### Migration

1. Create `tailwind.preset.js` at root.
2. Scaffold `openp41ge-components` (package.json, tsconfig, vite.config, tailwind.config, postcss.config, build scripts).
3. Implement icon registry + `<openp41ge-icon>`. Move all platform icons into registry.
4. Set up Storybook with icon stories.
5. Build row components using Tailwind + Shadow DOM.
6. Update `GitSidebarView` to import from `openp41ge-components`.
7. Add `openp41ge-components` to `pnpm-workspace.yaml` and register source alias in the main app's `vite.config.ts`.
8. Do NOT change explorer sidebar or `repo-tree-renderer.ts`.
